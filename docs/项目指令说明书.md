# 项目指令说明书

更新时间：2026-07-31

本文档整理 Telegram 查记机器人的主要使用指令、权限要求、格式示例和维护命令。文档只记录非敏感信息；机器人 Token、后台 Token、WebApp 密钥、银行卡接口密钥、TronGrid API key、生产 `.env`、数据库、日志、私钥均不得写入仓库。

## 1. 使用范围

本项目是 Go 版 Telegram 查记与群组运营机器人，主要能力包括：

- 群账记账、下发、账单、撤回、导出。
- 汇率、费率、换算、比价、实时汇率查询。
- 地址验证、下发地址、专属地址、TRC20 链上查询。
- 操作人、全局操作人、全局权限人、群标签、群类型、群控面板。
- 自动回复、关键词转发、自定义内容、群发、定时群发。
- 私聊菜单、购买/订单、入群教程、WebApp 群控入口。
- 本地构建、测试、定时部署、线上健康检查。

## 2. 权限说明

| 角色 | 说明 | 常见能力 |
| --- | --- | --- |
| 普通群员 | 群内普通成员 | 计算器、比价、地址验证、部分查询类命令 |
| 本群操作人 | 被设置到当前群的操作人 | 记账、查单、账单、汇率、群发、自动回复等日常操作 |
| 全局操作人 | 跨群操作人 | 可在多群使用操作人能力，具体以机器人权限判断为准 |
| 本群权限人 | 当前群 owner/权限人 | 设置/删除操作人、转移权限、设置欢迎语、地址等敏感配置 |
| 全局权限人 | 跨群权限人 | 管理全局操作人、跨群配置和更高权限操作 |

注意：

- 群内普通成员无权限执行管理命令时通常静默，不一定会返回“权限不足”。
- 危险命令需要二次确认，例如清空数据类操作。
- 群控面板和 WebApp 仍会走同一套权限校验。

## 5. 普通群员可用命令

### 5.1 四则计算器

普通群员可以直接发送四则表达式：

```text
1+2*3
100/4
-1/26000
10000*(1-0.11)/205
```

机器人返回：

```text
计算结果：7
```

说明：

- 支持 `+`、`-`、`*`、`/`、括号、小数。
- 支持 `x`、`X`、`×` 表示乘号，`÷` 表示除号。
- 纯数字不会触发计算器。
- `-1/26000` 会作为四则运算处理，不会记为下发。

### 5.2 费率汇率比价

默认金额固定为 `100000`，用户不需要输入金额。

单行格式：

```text
比价 11-205 10-210 10-220
```

多行格式：

```text
金额最大
11-205
10-210
10-220
```

别名：

```text
比价
金额最大
方案比较
```

计算公式：

```text
金额*(1-费率/100)/汇率
```

返回示例：

```text
比价结果（默认金额：100000，越大越好）
公式：金额*(1-费率/100)/汇率

1. 11-205 = 434.15 最高
2. 10-210 = 428.57，较最高低 1.28%
3. 10-220 = 409.09，较最高低 5.77%

相互增率：
11-205 比 10-210 高 1.3%
11-205 比 10-220 高 6.12%
10-210 比 10-220 高 4.76%
```

限制：

- 至少 2 组方案。
- 最多 10 组方案。
- 每组格式为 `费率-汇率`，例如 `11-205`。
- 费率必须大于等于 0 且小于 100，汇率必须大于 0。

### 5.3 地址验证和地址查询

普通群员可发送地址进行验证：

```text
验证地址 Txxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Txxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
0x1234567890abcdef1234567890abcdef12345678
```

普通群员可查询已配置地址：

```text
地址
下发地址
专属地址
```

说明：

- 普通群员发送裸 TRC20 地址也可以触发验证。
- 地址管理类命令仍需要权限人/操作人权限。

## 14. 高危操作说明

以下类型操作必须谨慎：

- 清空账单、清除数据、批量更新、机器人退出群组。
- 修改操作人、全局操作人、全局权限人。
- 修改下发地址、专属地址、联行号覆盖。
- 定时部署、线上重启、回滚。

机器人对部分高危操作有二次确认机制。出现确认提示后，必须在指定时间内发送提示中的确认命令，否则操作不会执行。

## 16. 定时部署说明

脚本：

```bash
scripts/schedule_ledgerbot_3am_deploy.sh
```

查看帮助：

```bash
./scripts/schedule_ledgerbot_3am_deploy.sh --help
```

默认行为：

- 不加 `--confirm` 时只打印部署计划，不上传、不创建 timer。
- 不传 `--when` 时默认安排到下一个 `03:00:00 Asia/Shanghai`。
- 传 `--artifact` 时使用指定本地二进制，不重新构建。
- 不传 `--artifact` 时脚本会先跑测试，再构建二进制。

示例：只预览计划：

```bash
./scripts/schedule_ledgerbot_3am_deploy.sh
```

示例：安排到指定时间：

```bash
./scripts/schedule_ledgerbot_3am_deploy.sh \
  --confirm \
  --artifact "/tmp/ledgerbot-release" \
  --when "2026-08-01 01:00:00"
```

脚本支持环境变量覆盖：

```text
SSH_KEY
REMOTE
REMOTE_DIR
SERVICE
TARGET_TZ
REMOTE_HEALTH_URL
REMOTE_READY_URL
```

部署脚本会：

1. 校验本地 artifact 存在。
2. 计算本地 SHA256。
3. 上传到远程暂存文件。
4. 上传远程 scheduled deploy 脚本。
5. 校验远程暂存 SHA256。
6. 创建或更新 systemd timer。
7. 到点后备份旧二进制、替换新二进制、重启服务、检查 `/healthz` 和 `/readyz`。

## 17. 线上核验命令

生产服务器信息以 README 中“线上部署事实”为准。常用核验：

```bash
SSH_KEY="/home/eren/桌面/shuai/deploy/ssh/orderflow_43_156_119_108_rsa"
REMOTE="root@43.156.119.108"
REMOTE_DIR="/opt/bilibili-ledgerbot-20260704"

ssh -i "$SSH_KEY" "$REMOTE" "systemctl is-active bilibili-ledgerbot.service"
ssh -i "$SSH_KEY" "$REMOTE" "systemctl show bilibili-ledgerbot.service -p MainPID -p ActiveEnterTimestamp --no-pager"
ssh -i "$SSH_KEY" "$REMOTE" "curl -fsS http://127.0.0.1:18080/healthz"
ssh -i "$SSH_KEY" "$REMOTE" "curl -fsS http://127.0.0.1:18080/readyz"
ssh -i "$SSH_KEY" "$REMOTE" "journalctl -u bilibili-ledgerbot.service -n 100 --no-pager"
```

查看某个定时部署 timer：

```bash
ssh -i "$SSH_KEY" "$REMOTE" \
  "systemctl list-timers --all 'ledgerbot-deploy-YYYYMMDD_HHMMSS.timer' --no-pager"
```

查看 staged 二进制和当前运行二进制 SHA：

```bash
ssh -i "$SSH_KEY" "$REMOTE" \
  "sha256sum $REMOTE_DIR/ledgerbot.next_YYYYMMDD_HHMMSS $REMOTE_DIR/ledgerbot"
```

查看定时部署日志：

```bash
ssh -i "$SSH_KEY" "$REMOTE" \
  "tail -120 '$REMOTE_DIR/logs/deploy_scheduled_YYYYMMDD_HHMMSS.log'"
```
